# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
В ходе анализа проекта было установлено: в приложении используются две сущности, которые описывают данные, — товар и покупатель. Их можно описать такими интерфейсами:

Интерфейсы данных
IProduct — Товар
Интерфейс описывает единицу товара, отображаемого в каталоге и доступного для покупки.

`interface IProduct { 
    id: string; 
    description: string; 
    image: string; 
    title: string; 
    category: string; 
    price: number | null; }`

Назначение: хранит данные одного товара, которые отображаются в каталоге, в модальном окне подробного просмотра и передаются в корзину.

IBuyer — Покупатель
Интерфейс описывает данные покупателя, необходимые для оформления заказа.

`interface IBuyer { 
    payment: TPayment; 
    email: string; 
    phone: string; 
    address: string; }`

Назначение: представляет данные, введённые пользователем на этапе оформления заказа. Используется для проверки валидности и формирования итогового заказа.

TPayment — Тип оплаты
Представляет выбранный пользователем способ оплаты.

type TPayment = 'card' | 'cash' | null;

Назначение: определяет доступные варианты оплаты.

Модели данных
Модели данных отвечают за хранение и работу с данными без привязки к отображению. Всего используются три модели: каталог, корзина, покупатель.

Модель каталога (CatalogModel)
Отвечает за хранение списка всех товаров и выбранного товара для подробного отображения.

Зона ответственности:

хранение массива товаров, полученных от API;
хранение текущего выбранного товара;
выдача товаров по запросу других частей приложения.
Поля класса:

products: IProduct[] Хранит все товары, полученные с сервера.

selectedProduct: IProduct | null Хранит товар, выбранный пользователем для подробного просмотра.

Методы класса:

setProducts(products: IProduct[]): void Сохраняет массив товаров.

getProducts(): IProduct[] Возвращает массив товаров каталога.

getProductById(id: string): IProduct | undefined Ищет товар по id.

setSelectedProduct(product: IProduct): void Сохраняет выбранный товар.

getSelectedProduct(): IProduct | null Возвращает товар для подробного отображения.

Модель корзины (CartModel)
Хранит товары, выбранные пользователем для покупки, и предоставляет методы для работы с корзиной.

Зона ответственности:

управление товарами в корзине;
подсчёт стоимости и количества товаров.
Поля класса:

items: IProduct[] Массив товаров, добавленных в корзину.
Методы класса:

getItems(): IProduct[] Возвращает массив товаров корзины.

addItem(product: IProduct): void Добавляет товар в корзину.

removeItem(product: IProduct): void Удаляет товар из корзины.

clear(): void Полностью очищает корзину.

getTotal(): number Возвращает суммарную стоимость всех товаров.

getCount(): number Возвращает количество товаров.

hasItem(id: string): boolean Проверяет, есть ли товар с таким id.

Модель покупателя (BuyerModel)
Хранит данные покупателя, которые он вводит при оформлении заказа, и выполняет их валидацию.

Зона ответственности:

сохранение отдельных полей данных покупателя;
валидация каждого поля и всей формы;
очистка данных после оформления заказа.
Поля класса:

data: IBuyer = { payment: null, email: '', phone: '', address: '' } Объект с данными покупателя, хранит значения:
payment: TPayment | null Вид оплаты
email: string Email покупателя
phone: string Телефон
address: string Адрес доставки
Методы класса:

setField(field: K, value: IBuyer[K]): void Сохраняет одно поле без удаления других.

getData(): IBuyer Возвращает все данные покупателя.
clear(): void Очищает все поля.
validate(): Record<string, string> Возвращает объект ошибок. Пустые поля получают текст ошибки, валидные поля отсутствуют в объекте.

Пример возвращаемого значения:

{ payment: 'Не выбран вид оплаты', email: 'Укажите email' }

### Слой комунникации
Класс ApiService Класс отвечает за взаимодействие приложения с сервером. Он использует методы класса Api для получения данных с сервера и отправки данных на сервер.

Конструктор:

constructor(api: IApi) api: IApi — объект класса Api, который содержит методы get и post для работы с сервером.
Поля класса:

private api: IApi — хранит объект класса Api для использования его методов внутри класса.
Методы класса:

async fetchProducts(): Promise<IProduct[]> Выполняет GET-запрос на эндпоинт /product/ и возвращает массив товаров IProduct[].

async sendOrder(orderData: IBuyer & { products: IProduct[] }): Promise Принимает объект с данными покупателя и товарами, выполняет POST-запрос на эндпоинт /order/ и возвращает объект, полученный от сервера после успешной отправки заказа.

catalog:item-select

Используется для открытия модального окна с подробным просмотром товара.
События карточки товара
product:add
Генерируется при нажатии на кнопку добавления товара в корзину в карточке предпросмотра (CardPreview).
Используется для добавления товара в корзину.
События корзины
basket:open
Генерируется при клике на иконку корзины в шапке сайта (Header).
Используется для открытия модального окна корзины.

basket:item-remove
Генерируется при удалении товара из корзины (CardBasket).
Используется для удаления товара из модели корзины и обновления отображения.

basket:order
Генерируется при нажатии на кнопку “Оформить” в корзине (Basket).
Используется для перехода к шагу оформления заказа.

События форм оформления заказа
order:change
Генерируется при изменении данных в форме выбора способа оплаты и адреса доставки (OrderForm).
Используется для обновления данных покупателя и выполнения валидации.

order:submit
Генерируется при отправке формы выбора способа оплаты и адреса доставки (OrderForm).
Используется для перехода к форме ввода контактных данных.

contacts:change
Генерируется при изменении email или номера телефона в форме контактов (ContactsForm).
Используется для обновления данных покупателя и выполнения валидации.

contacts:submit
Генерируется при отправке формы контактных данных (ContactsForm).
Используется для отправки заказа на сервер.

События модального окна
modal:open
Генерируется при открытии модального окна (Modal).
Используется для управления состоянием интерфейса.

modal:close

success:close
Генерируется при нажатии на кнопку “За новыми покупками!” (Success).

События моделей данных
События каталога
catalog:changed
Генерируется в модели каталога (CatalogModel) после сохранения списка товаров
(метод setProducts).
Используется презентером для обновления отображения каталога на главной странице.

product:selected
Генерируется в модели каталога (CatalogModel) при изменении выбранного товара
(метод setSelectedProduct).
Используется презентером для открытия модального окна с подробной карточкой товара.

#### События корзины
basket:changed
Генерируется в модели корзины (CartModel) при любом изменении её содержимого
(добавление товара, удаление товара, очистка корзины).
Используется презентером для:
обновления счётчика товаров в шапке;
перерисовки списка товаров в корзине;
обновления итоговой стоимости.
События покупателя
buyer:changed
Генерируется в модели покупателя (BuyerModel) при изменении любых данных покупателя
(ввод адреса, email, телефона, выбор способа оплаты, очистка данных).
Используется презентером для:
повторной валидации форм;
управления активностью кнопок отправки форм.
Презентер
Отвеачает за связывание слоев представление и модели данных
